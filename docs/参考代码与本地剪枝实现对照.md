## 1. 总结

新参考代码补齐了 A-FRCNN-12 和 SuDoRM-RF 的 mask 模型、物理剪枝和微调代码，使此前基于论文推断的实现可以进行源码级核对。两套实现的**剪枝位置和通道依赖关系基本一致**，但 mask 采样、最终 mask 生成、参数预算约束和剪枝后权重继承方式存在重要差异。

最关键的结论有四点：

1. 本地 A-FRCNN-12、SuDoRM-RF 目前使用的“精确参数预算投影”不是参考代码的方法。参考代码没有显式稀疏率损失或参数预算约束，而是用阈值 0.7 对随机 Gumbel mask 二值化。
2. 参考代码保存的是最后一次 forward 产生的随机 mask，而不是由最终 `alpha` 确定性生成的 mask。这会带来显著的种子和最后一个 batch 依赖。
3. 参考代码在物理剪枝后只继承部分卷积权重。对 SuDoRM-RF 来说，大量归一化、偏置和 `res_conv` 参数被重新初始化；这很可能是其剪枝后 1 epoch 性能下降特别大的主要原因之一。
4. 当前长程训练应继续保留。它代表“论文参数预算 + 完整权重继承”的稳定复现分支，但不能再标记为“参考源码完全一致”。后续应另开 source-faithful 分支，而不是覆盖当前结果。

### 2026-08-13 实验口径决定

本项目决定不再启动参考代码的严格复现实验。后续以当前实现作为主要复现结果，统一命名为 **SepPrune 预算约束复现版（budget-aligned structured pruning）**：剪枝位置遵循论文，目标参数量对齐论文报告，最终 mask 确定性生成，并完整继承所有存活权重及其依赖状态。参考代码仅用于验证剪枝位置、物理依赖和分析论文结果，不作为后续 GPU 实验分支。

报告结果时必须同时注明：全局参数预算投影是为增强模型规模可比性和实验可重复性而加入的实现补充，不应声称为作者代码的逐行复现。

## 2. 剪枝位置对照

| 模型 | 参考代码剪枝位置 | 本地实现 | 对齐情况 |
|---|---|---|---|
| TDANet | `sm.unet.globalatt.mlp.fc1` 的 1,024 个隐藏通道；同步裁剪 `fc1 → dwconv → fc2` | 相同 | 对齐 |
| A-FRCNN-12 | 共享 Blocks 中四个 `concat_layer` 的 512 通道输出；同步裁剪 `last_layer` 对应输入组 | 相同 | 对齐 |
| SuDoRM-RF | 16 个 UConvBlock 的 `proj_1x1` 512 通道隐藏路径；同步裁剪五个 depthwise stage、final norm 和 `res_conv` 输入 | 相同 | 对齐 |

因此，我们此前对剪枝维度和结构依赖的分析是正确的，不需要推翻物理模型的结构设计。

## 3. Mask 学习算法对照

| 项目 | 参考代码 | 本地当前实现 | 影响 |
|---|---|---|---|
| `alpha` 初始化 | `Uniform(0, 1)`，直接作为 sigmoid 前的值 | 预算版 `Uniform(-0.01, 0.01)` logits；TDANet 非预算版先采样 keep probability 再转 logits | 初始保留概率分布不同 |
| 随机噪声 | 单个 Gumbel：`-log(-log(U))` | 两个 Gumbel 之差，即 Logistic/Binary-Concrete 噪声 | mask 采样分布不同 |
| 温度 | 1.0 | 1.0 | 对齐 |
| 二值阈值 | 0.7 | 预算版不使用 0.7，改为全局预算投影；TDANet 非预算版使用 0.7 | A/S 不对齐 |
| STE | `LBSign`：forward 硬阈值，backward 截断到 `[-1,1]` | `hard + prob - stop_grad(prob)`，另做梯度裁剪 | 梯度细节不同 |
| 可训练参数 | 只训练 mask alpha，骨干冻结 | 只训练 mask controller，骨干冻结 | 原则对齐 |
| 优化器 | Adam，lr=0.1，weight decay=0 | 相同 | 对齐 |
| mask 阶段梯度裁剪 | Lightning `gradient_clip_val=5.0` | 1.0 | 不对齐 |
| 训练损失 | PIT pairwise negative SNR | 相同 | 对齐 |
| 音频片段 | 2 秒 | 2 秒 | 对齐 |
| 数据量 | loader 被截取为 500 batches；A/TD batch=1，SuDo batch=8 | 固定 500 updates；A batch=1，SuDo batch=8，TD batch=1 | 更新次数基本对齐；SuDo 实际样本数均为 4,000 |
| 最终 mask | 最后一次 forward 的随机 `module.mask.msk` | 由最终 logits 确定性生成并投影到论文参数预算 | 显著不对齐 |
| 参数预算 | 无显式约束 | A=3.06M、SuDo=1.54M 的硬预算投影 | 显著不对齐 |

说明：参考代码中没有 pruning pooling。此前所说的 “pooling rate” 如果指剪枝控制值，准确名称应为**二值化阈值 `epsilon=0.7`**；TDANet 网络内部的 adaptive average pooling 是特征融合操作，与通道剪枝率无关。

## 4. 物理剪枝与权重继承对照

### 4.1 A-FRCNN-12

参考代码重新创建四个 `concat_layer` 和一个 `last_layer`，随后只拷贝五个卷积的 `weight`：

- 没有拷贝卷积 bias；
- 没有拷贝 GlobLN 的 gamma/beta；
- 没有拷贝 PReLU 参数。

按当前本地通道数 `[339, 237, 174, 158]` 计算，参考方式会重新初始化 4,265 个参数，只占本地剪枝模型的约 0.14%。因此它会造成差异，但通常不是 A-FRCNN-12 的主导误差来源。

本地实现会复制所有保留通道的卷积 weight/bias、归一化参数和激活参数，权重继承更完整。

### 4.2 SuDoRM-RF

参考代码为每个 block 新建完整的 `UConvBlock`，只复制：

- `proj_1x1.conv.weight`；
- 五个 `spp_dw.*.conv.weight`。

以下参数没有从原模型继承：

- `proj_1x1` 的 bias、GlobLN 和 PReLU；
- 五个 depthwise stage 的 bias 和 GlobLN；
- `final_norm`；
- 整个 `res_conv.weight` 和 `res_conv.bias`。

按当前 16 层通道数计算，共约 **634,040 个参数重新初始化，占 1.54M 剪枝模型的 41.17%**。这不是轻微数值差异，而是实质性的部分随机重初始化。

这与已有结果高度一致：

| SuDoRM-RF 阶段 | 论文/参考实验 SI-SDRi | 本地完整继承 SI-SDRi |
|---|---:|---:|
| 剪枝后 1 epoch | 4.06 | 6.33 |

本地实现完整继承所有依赖参数，因此 1-epoch 恢复明显更好。论文最终结果仍可能通过长程训练恢复，但两者代表不同的初始化条件。

### 4.3 TDANet

参考代码与本地实现都裁剪 `fc1` 输出、depthwise convolution 和 `fc2` 输入。参考微调脚本只显式拷贝这三个 convolution weight，没有拷贝裁剪后 `fc1` 的 GlobLN 参数；本地实现会完整复制对应归一化状态。

参考目录仍缺少单独的 `tdanet_pruned.py` 源文件，但 `tdanet_v2.py` 和 `finetune_tdanet.py` 已足以确认主要剪枝链路。

## 6. 参考代码本身的可运行性问题

这份代码更像作者实验目录快照，不是开箱即用的发布包：

1. 数据、checkpoint、mask 和输出路径均硬编码为作者机器上的 `/public/...`。
2. 三个 `finetune_*.py` 当前实际启用的是 LibriMix mask 路径，LRS2 路径处于注释状态，直接运行会跑错实验。
3. mask-learning 的输出文件名与 finetune 脚本期望的 LRS2 文件名不一致，需要人工改名或改路径。
4. `sudormrf.pth` 只有 6.3MB，PyTorch 报 zip central directory 缺失；压缩包中的原文件也是同样大小，属于损坏或截断 checkpoint。
5. A-FRCNN-12 和 TDANet checkpoint 可以安全读取；TDANet 参考 checkpoint 与我们此前使用的 Hugging Face checkpoint 权重不同。
6. mask 保存依赖最后一个随机 forward，未显式切换到确定性推理，严格复现时必须保留这一行为并固定完整 RNG 状态。
7. SuDoRM-RF mask 配置写了 5 epochs，但输入是单个 `itertools.islice(..., 500)`；该 iterator 第一轮耗尽后是否会被训练框架正确重建存在疑问。有效更新数很可能仍主要来自首轮 500 batches。

## 8. 已归档的参考实现对照矩阵

以下矩阵保留为方法审计记录；根据 2026-08-13 的实验决定，只继续 B 分支，不启动 R-exact、R-mask 或 R-budget：

| 分支 | mask 算法 | 参数预算 | 物理剪枝继承 | 目的 |
|---|---|---|---|---|
| B（正在运行） | 本地 Binary-Concrete + 全局预算投影 | 精确对齐论文 | 完整继承 | 稳定且参数量可比的工程复现 |
| R-exact | 参考代码：单 Gumbel + threshold 0.7 + 最后随机 mask | 无显式预算 | 只拷贝参考脚本中的 weight | 复现参考代码及论文 1-epoch 现象 |
| R-mask | 参考 mask 算法 | 无显式预算 | 完整继承 | 分离 mask 算法与权重继承缺失的影响 |
| R-budget | 参考 mask 学习后做参数预算对齐 | 对齐论文 | 完整继承 | 检查论文参数规模与参考 mask 的兼容性 |

原建议执行顺序（已归档，不再执行）：

1. 不打断当前 A/S 长程训练，继续保存 `best.pt`。
2. 当前训练结束后，先对 A-FRCNN-12 和 TDANet 的参考 checkpoint 跑完整原始模型测试，确认其是否对应论文基线。
3. 用同一 baseline、同一 seed、同一 500 batches 跑 `R-exact` 与 `R-mask`，先做微调前和 1-epoch 完整测试。
4. SuDoRM-RF 的 source-faithful 实验暂用本地 baseline；若要严格复现作者起点，需要重新取得未损坏的 SuDoRM-RF checkpoint。
5. 只有当 1-epoch 对照验证无误后，再启动耗时较长的 R 分支最终收敛训练。
