## 2026-08-10：跨模型剪枝重建审计与首轮 mask 搜索

公开仓库的 A-FRCNN/SuDoRM-RF mask 脚本依赖未发布的
`afrcnn_pruned.py`、`sudormrf_pruned.py` 和 `ChannelMask1D`。根据公开
`finetune_*.py` 暴露的通道依赖，新增独立重建：A-FRCNN 剪四个 fusion
输出及 `last_layer` 对应输入；SuDoRM-RF 剪 16 个 UConv block 的内部
512 通道路径。物理剪枝会同步复制卷积权重/偏置、归一化参数、PReLU 和
输出投影；公开微调脚本只复制部分卷积权重，会导致其余参数被随机初始化，
本重建不复现这个明显的数据迁移缺口。

两模型均通过以下检查：

- 全通道物理重建与原模型输出最大绝对误差为 0；
- 半通道模型参数下降且前向形状/有限值正确；
- 4/16 组 mask 均有非零有限梯度；所有冻结权重均无梯度；
- 真实 32,000-sample LRS2 batch smoke 通过；SuDoRM-RF 的公开 mask YAML
  所写 batch size 8 也通过；
- 剪后 SuDoRM-RF 两步微调及 3 条测试样本 SDRi/SI-SDRi 管线通过。

论文明确称 mask 搜索为 500 iteration；但公开 SuDoRM mask YAML 写 5
epoch，脚本又将每个 epoch 截为 500 batch，实际等于 2,500 update。当前
主口径采用论文的 500 update，同时采用 YAML 的模型专用 batch size
（A-FRCNN=1、SuDoRM-RF=8）。

首轮 epsilon=0.7、seed=2026、500-step 诊断结果：

| 模型 | 初始化概率范围 | 保留通道 | 剪后参数 | 论文参数 |
|---|---:|---|---:|---:|
| A-FRCNN-12 | 0.55–0.85 | 468/449/441/380 | 4.582 M | 3.06 M |
| A-FRCNN-12 敏感性 | 0.01–0.99 | 434/372/368/306 | 4.108 M | 3.06 M |
| SuDoRM-RF | 0.55–0.85 | 16 层见 result.json | 1.632 M | 1.54 M |

A-FRCNN 两种初始化均明显偏离论文规模；仅把学习后的决策阈值从 0.7
提高至约 0.97 才能得到 3.038 M。任务损失单独优化独立 Bernoulli mask 会
持续推动更多通道开启，因此作者私有 `ChannelMask1D` 中必然还有论文与
公开仓库没有充分定义的竞争、归一化或稀疏约束。该问题会实质改变剪枝
结构，当前不把首轮 A-FRCNN mask 当作论文主结果，也不直接启动长时间
微调；它们保留为可审计的诊断实验。

### 论文引导的参数预算重建

为在不伪造私有实现的前提下继续实验，新增一个显式补全版本：保留论文
给出的 Gumbel 随机化、硬二值前向、裁剪 STE、冻结骨干、500 update 和
mask learning rate 0.1；将论文未闭合的稀疏约束明确实现为“每次前向把
hard mask 投影到 Table 2 报告的物理参数预算”。梯度通过 Binary Concrete
连续概率回传。每层至少保留一个通道，控制器按每个候选通道实际影响的

A-FRCNN-12，seed 11，TR/TT 各随机 600 条，`inference_mode()`，PIT-best
SI-SDR，A100 上耗时 147.6 秒。四个模型共享同一冻结起点（dense `best.pt`
sha256 `6f9dc2c7…`，masks sha256 `13a774ee…`）：dense、pruned@init、
pruned@20k updates（`epoch1.pt`）、pruned@800k updates（`best.pt`）。

三项结论直接改写了方案（详见 `docs/数据剪枝与模型剪枝协同方案调研.md`
v3 的 §4.2、§5、§9）：

| 检验项 | 实测 | 影响 |
|---|---|---|
| 「Gap = dense − pruned」是否独立于普通 hard mining | 原始 dB 差 ρ=0.809、子集重叠 0.822 | 原主方案与 hard-mining 基线不构成对照，改用 percentile-rank 差（ρ=0.497、重叠 0.631） |
| dense 教师在训练集上的记忆偏差 | TR 14.076 dB vs TT 11.393 dB，差 2.683；TR 的 sd 仅为 TT 的 47% | 不能声称 dense 估计了「不可约损失」；需加分位截断抗偏差检查 |
| 静态分数的时效性 | ρ(init, 20k)=0.484 / 0.429；ρ(init, 800k)=0.253 / 0.246（Gap_dB / Gap_rank） | 静态子集不能用于长程训练；主终点改为固定 40,000 updates |

另有两个支撑事实：

- 本数据集两个源的增益严格对称，混合语音自身的 PIT 平均 SI-SDR 为
  −0.015 dB（sd 0.184），因此 **SI-SDRi 与 SI-SDR 逐样本等价**，用哪个
  都不影响 Gap。
- `Gap_dB@init` 的逐样本最小值仍有 2.786 dB，即剪枝退化是全局性的；
  而第一个 epoch 内逐样本提升的最小值为 −5.460 dB，说明恢复过程中样本

算力方面，由 `validation.csv` 差分测得 A-FRCNN-12 每 epoch（20,000
updates + 5,000 条 CV 验证）为 3,584 秒，SuDoRM-RF 为 2,588 秒。按原
方案「训练到收敛 × 4 arm × 3 seed」需约 35 GPU-天，不可行；改为固定
40,000 updates 后单 run 约 1.93 小时，全部三个阶段约 40–47 小时。

| 子集 | 与 S2（hard mining）的 score-selected 重叠 | 平均 Q_dense | A 区占比 | C 区占比 |
|---|---:|---:|---:|---:|
| 全集 | — | 14.443 | 35.0% | 34.8% |
| S2 hard | 1.000 | 14.163 | 37.0% | 31.5% |
| S3 gap_db | 0.820 | 14.554 | 43.0% | 20.5% |
| **S3′ gap_rank** | **0.620** | **14.953** | **58.0%** | **13.0%** |
| S4 gap_rank_2d | 0.847 | 14.541 | 44.0% | 21.5% |

S3′ 确实集中在「dense 会、剪枝坏了」的 A 区并避开「两个都不会」的 C 区。
**S4 反而最接近 hard mining**（0.847）：在很窄的 `pct_dense` 带内按 `Gap_rank`
排序等价于按 `-pct_pruned` 排序，二维分层把 dense 轴的区分作用消掉了。S4 因此
从 A1 移出，标记为暂缓。

实现过程中发现两个数值问题，均已修正并写入调研文档 §13.2：

1. **打分器必须关闭 TF32。** A100 上 cuDNN 卷积默认启用 TF32（cuBLAS matmul 默认
   不启用，两者不对称）。batch 16 与 batch 1 的逐样本 SI-SDR 差异：TF32 开时
   dense 7.7e-4 dB、pruned 1.6e-3 dB；关闭后降到 2.9e-6 / 5.7e-6 dB。20,000 条
   分数分布在约 19 dB 上，相邻名次间距就是 ~1e-3 dB，TF32 噪声足以打乱 percentile
   rank。`score_lrs2.py` 无条件关闭；训练脚本只读取不修改默认值，以保持与既有
   finetune 流水线数值可比。
2. **共享 GPU 上没有逐位确定性。** GPU 空闲时两次相同训练逐位一致（72/72 张量
   Δ=0.0）；但另两个长程任务占用显存时，cuDNN 的显存感知算法选择可能改变，8 个
   Adam step 内放大到 3e-3。resume 验收因此改为断言逐步 loss 轨迹在 1e-2 dB 内
   一致（数据顺序错误会造成 dB 量级偏差），不再要求权重逐位相等。

另一个方案层面的修正：原计划让 S0 从 `finetune/epoch1.pt` 续跑 20k→40k 以省
约 1 小时，已放弃。该 checkpoint 前 20,000 步的数据顺序来自旧 DataLoader 的
shuffle，与新脚本的确定性 order 不同，拼接会让 S0 口径难以描述。S0 完整重跑，
`epoch1.pt` 只作为 E2 恢复阈值（10.522 dB）的数值来源。

实验本身在当前 A-FRCNN-12 / SuDoRM-RF 长程微调结束、GPU 空出后再启动。

## 2026-08-13：K0 蒸馏对照实现 + 长程微调进展

### K0（`distill_baseline.py`）

`L = (1-α)·PIT-NegSNR(student, targets) + α·NegSNR(student, teacher | 同一排列)`。
教师输出先按其自身 PIT 最优排列对齐到 ground truth，蒸馏项再**复用任务项选中的
排列**，避免两项把同一输出通道往两个说话人上拉。教师为冻结 dense（5,127,688
参数），`eval()` + `requires_grad_(False)` + `no_grad`。

蒸馏损失放在独立模块，由 `train_data_pruned.py` 在 `--distill-alpha > 0` 时调用，
**不新增训练循环**——K0 与所有数据 arm 走完全相同的训练代码，只差这一个标量。
`--distill-alpha 0` 时走的是原封不动的旧调用路径。

实测验证：

| 项 | 结果 |
|---|---|
| `α=0` 与 S0 逐位一致 | `max|Δweight| = 0.0`（6 步） |

regime 都成立、教师源顺序不变性 + 对齐幂等、α 线性插值、教师无梯度）。验收总数
24 → **29 项，全部通过**。

K0 不是算力对齐的 arm，比较只能在相同 update 数下读精度，墙钟单列。它不在

### 剪枝模型当前收敛值：11.344 dB，距论文 −0.906

用批量 SI-SDRi（关 TF32）在完整 3,000 条测试集上评测 `finetune/best.pt`

|---|---:|

| 本地 剪枝 1 epoch 10.522 | +0.822 |
| 论文 未剪枝 10.500 | +0.844 |

论文声称剪枝后比未剪枝提升 +1.75 dB；本地是 −0.14 dB。这是方向性不一致，不只是

### 根因：学习率 73 个 epoch 从未衰减

`ReduceLROnPlateau` 用 PyTorch 默认的 `threshold=1e-4, threshold_mode='rel'`，
在 val_loss ≈ −10.9 时只要求改进超过 0.0011 dB。A-FRCNN 最近 30 个 epoch 靠
+0.017 / +0.021 dB 的噪声级刷新反复清零 patience，形成自锁：LR 一次没降过，
早停也永不触发。用真实验证序列回放：

| 配置 | 会在哪些 epoch 降 LR |
|---|---|
| 当前（rel 1e-4） | **从未** |
| abs 0.05 dB | ep22 → 5e-4，ep43 → 2.5e-4，ep59 → 1.25e-4 |
| abs 0.02 dB | ep22 → 5e-4，ep56 → 2.5e-4 |

（回放只在 ep22 之前严格有效；之后的序列是在恒定 LR 下产生的，属反事实。）

对照组：SuDoRM-RF 在 ep32 降 LR（1e-3 → 5e-4），best 从 7.466 涨到 8.589，
**+1.123 dB**。A-FRCNN 自 ep6（10.834）起 66 个 epoch 只涨 0.124 dB。

`train_pruned_original.py` 新增两个**可选**参数（默认行为完全不变）：

- `--override-learning-rate`：在 `--resume` 之后强制 LR。必需，因为
  `optimizer.load_state_dict()` 会恢复 checkpoint 里的 LR 并静默覆盖
  `--learning-rate`。
- `--plateau-threshold`：以 dB 为单位的绝对改进阈值，同时作用于 scheduler 和
  早停计数；`best.pt` 的保存判据仍保持严格，确保存下来的是真正最好的权重。

### GPU 并发能力：batch=1 训练是延迟受限，可以并跑

`nvidia-smi` 报 94% 利用率具有误导性。实测：

|---:|---:|---:|---:|
| 2 | 173.7–177.8 | — | 5.6–5.8 step/s |
| 3 | 180.0 | +3.7% | 11.2 step/s |

显存 5 路合计约 5.2 GB / 40 GB。三个并发 arm 的速率差 <0.5%，条件公平。

**结论：数据剪枝 stage A 不必等长程微调结束，可以立刻并行开跑。** 其四个冻结
输入（dense `best.pt`、`masks.pt`、E2 阈值、`epoch1.pt`）全部已最终确定，且都

## 2026-08-20：SuDoRM-RF 跨模型验证 —— 判定为无法判定

25 个 run（S0/S1/S2/S3/S3′ × 5 seed @keep=1000 + 4 个保留率扫描点）全部完成，
116 个快照评测完毕。结论：**协议在此模型上没有分辨力，判定 inconclusive，
不作为对方法的否证。**

三条依据：

1. **保留率扫描无拐点**：全数据 6.412、keep=5000 6.435、keep=500 6.561、
   keep=200 4.469，在 4.5–6.9 间无规律跳动，不随保留率单调下降。没有数据量
   缺口，选择规则就没有可补回的东西。
2. **噪声压倒效应**：100 个快照中 8 个 <4 dB、3 个 <0 dB，最低 −44.56。
   S3 的 E1c 均值 0.653 完全由单个 −44.56 快照造成（中位数 5.897 才是真实
   水平）。全部对比 p ≥ 0.13。塌陷在各 arm 间大致均匀（S0 0/S1 3/S2 2/S3 2/
   S3′ 1），不由选择方法引起。
3. **根因是 40k updates 对该模型太早**：A-FRCNN 在 40k 处达收敛值的 93.6%，
   SuDoRM-RF 只有 68.7%，仍在优化混沌期，瓶颈是训练稳定性而非数据。

要在 SuDoRM-RF 上得结论需约 1M updates/run × 15 run，数周量级，不可行。

**建议改用 TDANet 做第二个模型**（@20k 已达 dense 的 93.9%，与 A-FRCNN 同属
快速稳定恢复类型）。并更正此前判断：**数据剪枝不需要预算对齐的 mask**，现有
TDANet mask（2,030,463 参数）够用；接入工作量是把 tdanet_seprune.py 的剪枝路径
接进 build_inherited_pruned_model，远小于实现 budgeted mask 搜索。
