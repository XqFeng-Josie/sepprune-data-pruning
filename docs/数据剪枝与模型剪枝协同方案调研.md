## 0. 本方案在项目中的位置（必须先明确）

```
dense 训练(136 ep) ──→ mask 搜索(500 step) ──→ 物理剪枝 ──→ 恢复微调(长程)
5,127,688 参数                                  3,059,372 参数        ↑
                                          参数量在这一步已定死    本方案只替换这一步的「数据供给」
```

三点边界，写在最前面避免误解：

1. **本方案不独立于当前剪枝实验**，它是 stage-3 的附加件。两个输入（dense `best.pt`、`masks.pt`）就是当前实验的产物，基线就是当前正在跑的全数据微调曲线。
2. **数据剪枝不降低任何参数量或 MAC。** 结构、mask、通道数、3,059,372 这个参数量全程不变。它影响的是「剪枝之后恢复性能所需的数据量与训练时间」。
3. **不在 dense 原模型上训练。** dense 只有两个角色：提供继承权重（当前流程已有）、当逐样本打分教师；它一次梯度都不更新。

因此本方案的命题是 A/B 两条，C 方向（用更好的数据选择换更激进的剪枝预算，从而真正降参数）确认为**后续工作**，见 §10.3：

- **A 训练效率**：剪枝后的性能恢复只需要一半训练数据 → 主指标为达到恢复阈值的 updates 与端到端墙钟。
- **B 固定预算性能**：同样 40,000 updates，模型剪枝感知的数据选择恢复得更高 → 主指标为固定 update 下的 TT SI-SDRi。

A 与 B 共用同一批 run，是同一组实验的两种读法。

## 1. 结论先行

1. 用户给出的论文 [*Winning the Pruning Gamble: A Unified Approach to Joint Sample and Token Pruning for Efficient Supervised Fine-Tuning*](https://arxiv.org/abs/2509.23873)（Q-Tuning）协调的是**样本级数据剪枝与 token 级数据剪枝**，不是「训练数据剪枝 + 神经网络参数剪枝」。它不能直接替换当前 SepPrune 的通道剪枝，但其「按当前模型状态识别冗余、噪声和校准样本」的思想可以迁移。
2. 当前三个模型都能做样本级数据选择。A-FRCNN-12 最适合作为首个验证对象：原始基线可靠、剪枝参数量已对齐论文预算、长程训练稳定，并且它在 20,000 updates 处已有完整测试集结果，可直接用作预注册的恢复阈值（见 §9.1、§9.3）。TDANet 适合作为第二个架构验证；SuDoRM-RF 当前存在基线偏低和训练波动，作为稳定性诊断对象。
3. LRS2-2Mix 本地训练集的 20,000 条样本均已是严格的 2.0 秒音频，所以不存在「从更长 utterance 中挑更有价值的 2 秒 crop」的空间。token 级思想只能改造成整条样本的选择，或把输入缩短为连续子段；**且缩短子段属于算力削减而非信息删除**（见 §10.1）。
4. 主方案是面向已剪枝模型的 **Dense–Pruned 分位差选择（Gap_rank）**：
   - 用原始 dense 模型估计样本的「固有可学性」；
   - 用剪枝模型估计「结构剪枝造成的退化」；
   - **两者先各自转成训练集内的 percentile rank，再作差**——这一步是 v3 的关键修正，不做分位化会让分数退化成普通 hard mining；
   - 优先训练「dense 能分、pruned 暂时分不好」的样本，对「两个模型都分不好」的样本限权。
5. 推荐实验顺序：功效闸门（S1 三 seed）→ 静态筛选（S0/S1/S2/S3/S3′，固定 40,000 updates）→ 存活 arm 补 seed → 动态刷新 → 时间子段 → 跨模型。

### 1.1 必须遵守的六条约束

1. **评分必须从同一起点产生**：A-FRCNN-12 使用原始 `best.pt` 与固定 `masks.pt` 重新构造「剪枝后、微调前」的物理模型；不能使用已经在全数据上训练数十个 epoch 的 pruned `best.pt` 作为起点。
2. **静态只与静态比较，动态只与动态比较**：固定子集必须对照固定随机子集；每周期重采样的 Random 必须对照动态更新的 Gap_rank。
3. **调度按 optimizer update 对齐，且第一轮完全关闭调度器**：主终点为固定 40,000 updates、常数学习率 1e-3、无 ReduceLROnPlateau、无 early stopping。这样彻底消除调度触发频率这个混淆源（合法性见 §9.1）。
4. **分数采用逐样本 SI-SDR，方向固定**：定义正 Gap 为「剪枝模型退化」。若打分器同时记录训练口径的 PIT-NegSNR，**必须显式传 `threshold_byloss=False`**——该开关在 batch=1 时是 no-op，但打分器为提速会用 batch>1，届时它会真的丢样本（见 §12.1）。
5. **只用训练集决定子集**：CV 只用于训练过程监控，TT 只在预先规定的 update 数上评测；禁止用 CV/TT 的逐样本表现调阈值或挑选训练样本。
6. **预注册**：在跑第一个正式 run 之前锁定分数定义、子集构造规则、恢复阈值、最小可检测效应（MDE）和 seed 列表，写入 `docs/` 并提交；不依据结果回改。

## 2. Q-Tuning 论文到底做了什么

### 2.1 基本问题

Q-Tuning 面向大语言模型的监督微调，同时控制两个数据预算：

- sample keep ratio：保留多少条训练样本；
- token keep ratio：在被保留的部分样本中再保留多少 token。

论文的主要实验设置为保留 12.5% 样本，并在需要 token 剪枝的样本中保留 50% token。论文在 [arXiv v2](https://arxiv.org/pdf/2509.23873) 中报告了性能和训练开销结果，但截至本调研日期，[作者官方仓库](https://github.com/gszfwsb/Q-tuning) 仍只包含说明材料，并明确写着代码仍在更新/准备发布，因而目前没有可直接审计和运行的官方实现。**本节所有数字来自论文文本，本项目未做独立复算。**

### 2.2 Error–Uncertainty Plane

论文对每条样本计算两个维度：

- Error：用样本 perplexity 表示当前模型的错误程度；
- Uncertainty：用预测分布的 entropy 表示模型的不确定性。

据此把样本分成四类：

| 区域 | Error | Uncertainty | 论文解释 | 操作 |
|---|---:|---:|---|---|
| Q1 | 高 | 高 | 噪声或有害样本 | 丢弃整条样本 |
| Q2 | 高 | 低 | 模型「自信但答错」的 misconception | 保留样本，对 token 剪枝 |
| Q3 | 低 | 低 | 已掌握、冗余知识 | 丢弃整条样本 |
| Q4 | 低 | 高 | 有价值的校准/困难样本 | 完整保留 |

阈值不是固定常数，而是在每个 mini-batch 内根据分位数动态搜索，使 Q2 与 Q4 的总数量满足 sample keep ratio。

### 2.3 Q2 的 token 剪枝

Q2 样本中的 token 由「当前 token 的 perplexity + 邻域 token perplexity」形成平滑分数，邻域权重系数默认 0.5；Q4 样本完整保留。

这里存在一个必须记录的复现风险：论文图注说高局部 PPL token 被删除，而正文公式和附录算法又写成保留分数最高的 token。两种表述方向相反，且官方代码尚未发布。因此即使在 LLM 上也不能声称已能逐行严格复现这一部分。

### 2.4 论文效率结果应怎样理解

论文报告完整 SFT 约 90 分钟，Q-Tuning 在 12.5% 样本、50% token 设置下约 65 分钟，墙钟时间节省约 28%；但被反向传播的数据比例理论上只有 6.25%。差异来自筛选阶段仍需额外前向计算。因此，迁移到语音分离时必须报告**真实墙钟时间**，不能把「保留数据比例」直接当作训练加速比例。本项目对应的处理见 §9.4 的效率口径。

## 3. 为什么不能原样用于当前语音分离

| Q-Tuning 前提 | 当前 SepPrune/LRS2 情况 | 影响 |
|---|---|---|
| 离散词表与 token 概率 | 模型输出连续波形 | 没有可直接计算的 token entropy/PPL |
| 一个 batch 内做二维分位数 | 原始及剪枝微调均为 batch size 1 | batch 内四象限在统计上无意义，必须改为全训练集分位 |
| token 可独立从 loss 中屏蔽 | 时域分离依赖连续波形和 PIT 对齐 | 随机删除离散点会造成不自然的时域跳变 |
| 文本 token 减少可缩短序列计算 | 本地数据已固定为 32,000 点/2 秒 | 必须真的缩短序列，单纯 loss mask 不会减少主要前向计算 |
| 噪声/有害样本确实存在（Q1 象限） | **LRS2-2Mix 是合成混合，无标注噪声** | Q1 象限在本数据集上没有对应物，见 §4.4 |
| 论文筛选只依赖当前 SFT 模型 | 我们同时拥有 dense 与 pruned 模型 | 可以使用更直接的「剪枝敏感度」信号，是本任务的优势 |

本地已核实的数据与接口事实（v3 全部重新验证通过）：

- TR/CV/TT 分别为 20,000 / 5,000 / 3,000 条；TR 抽检 200 条，`(frames, samplerate)` 集合唯一为 `{(32000, 16000)}`，即严格 2.0 秒定长，现有 `LRS2MixDataset` 的随机裁剪确为 no-op。
- 全部 20,000 组训练音频流式检查通过：mix/s1/s2 均为 16 kHz、32,000 点，无 NaN/Inf、无近静音源；`mix ≈ s1+s2` 的相对 RMSE 平均约 `1.07e-4`、最大约 `2.79e-4`，属 PCM16 量化误差量级。
- 文件名格式为 `spk1_utt1_+x_spk2_utt2_-x.wav`，**两个源的增益严格对称**。TR/CV/TT 分别含 2,884 / 68 / 144 个说话人标识，三个 split 两两无交集；`|x|` 在 [0.00, 5.00] 近似均匀（TR 四分位 1.25 / 2.51 / 3.77）。因此 §9.2 的 SNR 分位分层可行，混合 SNR 差为 `2|x| ∈ [0, 10] dB`。
- TDANet、A-FRCNN-12、SuDoRM-RF 均已用 16,000、22,400、32,000 点输入做过无梯度前向检查，三个模型都能返回同长度双源输出。
- 逐样本 SI-SDRi 打分链路已存在，`reproduction/evaluate_pruned_original.py` 的 `best_si_sdr` 与逐行 CSV 输出可直接复用。

## 4. 面向当前任务的分数定义

### 4.1 样本质量

对第 i 个混合语音，用与正式评测相同的 PIT-best SI-SDR：

```text
Q_dense(i)  = SI-SDR(dense(x_i),  y_i)     # PIT 取最优排列
Q_pruned(i) = SI-SDR(pruned(x_i), y_i)     # pruned 指「剪枝后、微调前」的冻结起点
```

> **v3 修正**：v2 主张用 SI-SDRi「显式记录混合语音自身的基线难度」，这条在本数据集上不成立。因为文件名中两个源的增益严格对称（`+x` / `−x`），PIT 平均后混合语音自身的基线精确抵消：实测 600 条 TR 上 `mixture SI-SDR = 均值 −0.015，sd 0.184，min −0.849，max +0.676`（§5）。所以 **SI-SDRi 与 SI-SDR 逐样本等价**（差异 sd 仅 0.18 dB，不足 `Q_dense` 标准差的 12%），Gap 更是对这个选择完全不变。用 SI-SDRi 没有错，但理由只能是「与正式评测口径一致」，不能声称它多带了难度信息。真正的外生难度信息在 `|SNR|`、说话人同一性/性别里，必须单独记录。

打分使用 eval mode + `inference_mode()`、逐样本计算、无随机增强，不能先做 batch mean。dense 与 pruned 的 PIT 排列各自独立取最优；如果另外计算两模型的波形 disagreement，则必须先用目标源把二者排列对齐。

### 4.2 主分数：Dense–Pruned 分位差 Gap_rank

```text
pct_dense(i)  = Q_dense(i)  在全部 20,000 条 TR 中的 percentile rank ∈ [0,1]
pct_pruned(i) = Q_pruned(i) 在全部 20,000 条 TR 中的 percentile rank ∈ [0,1]

Gap_rank(i) = pct_dense(i) - pct_pruned(i)          ← 主分数
Gap_dB(i)   = Q_dense(i)   - Q_pruned(i)            ← 仅作消融，不作主方案
```

> **v3 修正（本轮最重要的一条）**：v2 的主分数是 `Gap_dB`。实测表明它与「高 pruned loss」几乎共线，因此 v2 的 S2/S3 在设计上不构成对照。原因是两项方差悬殊：`sd(Q_dense)=1.63`，`sd(Q_pruned)=3.59`，差值被 pruned 项主导。先分位化再作差可使两个轴等权。实测（§5，600 条 TR）：

| 分数 | ρ(score, pruned loss) | ρ(score, Q_dense) | 与 S2 的 top-37.5% 重叠 | 所选子集平均 Q_dense |
|---|---:|---:|---:|---:|
| pruned loss（S2 基线） | 1.000 | −0.453 | — | 13.39 |
| `Gap_dB`（v2 主方案） | **0.809** | +0.082 | **0.822** | 14.14 |
| **`Gap_rank`（v3 主方案）** | **0.497** | +0.513 | **0.631** | **14.79** |
| （随机基准 / 全集） | 0 | 0 | 0.375 | 14.08 |

`Gap_dB` 选出的 7,500 条里约 6,170 条与纯 hard mining 相同，真正不同的只有 ~1,330 条（占 10,000 条预算的 13%），几乎肯定小于 seed 噪声。`Gap_rank` 的差异扩大到 ~2,770 条（28%），且所选子集的平均 `Q_dense` 从「低于全集」（S2 的 13.39 < 14.08）翻转为「高于全集」（S3′ 的 14.79），即它确实在避开「两个模型都不行」的样本——这正是本方案要检验的机制。三者的 `|SNR|` 均值接近（2.14 / 2.10 / 2.20，全集 2.53），说明差异不是简单地由混合难度驱动。

这个定义与 [RHO-LOSS](https://proceedings.mlr.press/v162/mindermann22a.html) 的 reducible loss 思想接近，但这里的 reference 不是单独训练的 holdout 模型，而是已经看过同一训练集的原始 dense 模型。因此它不能被称为「不可约损失」的无偏估计，只能称为 **teacher-restoration / pruning-sensitivity score**。dense 的记忆偏差量级已实测，见 §5.2 与 §12.1 的抗偏差检查。

### 4.3 连续输出的不确定性替代（第二阶段）

按成本从低到高可选：

1. **跨 checkpoint 波动**：记录同一样本在若干阶段 checkpoint 上的 SI-SDR 标准差；最贴近 training dynamics，但要保存/重复评分。
2. **dense–pruned disagreement proxy**：PIT 对齐两个模型输出后计算波形/STFT 差异；它是结构敏感度代理，不是严格的概率不确定性。
3. **轻微增强一致性**：对响度等保持标签语义的变换做 K 次前向。注意时间平移在 2 秒定长片段上需要补零或裁剪，会改变内容；且分离模型近似平移等变，该信号可能接近退化，优先级最低。

第一轮不上 MC-dropout：三个模型没有统一可靠的 dropout 不确定性接口，额外 K 次前向也会削弱数据剪枝的收益。

### 4.4 二维选择平面（S4 备选）

坐标改为 `pct_dense` 与 `Gap_rank`，两者实测 ρ=+0.513，仍有区分度：

| 区域 | pct_dense | Gap_rank | 判断 | 建议采样权重 |
|---|---:|---:|---|---:|
| A | 高 | 高 | dense 学得会且对剪枝结构敏感，恢复价值最高 | 最高 |
| B | 高 | 低 | 容易且剪枝后仍保持，冗余 | 低，但保留随机探索比例 |
| C | 低 | 低 | **当前容量下不可学**（非噪声，见下） | 限权，不全丢 |
| D | 低 | 高 | 困难且剪枝后进一步退化 | 中高；结合稳定性再判断 |

> **v3 修正**：v2 把 C 区称为「疑似噪声/标签质量问题」。这在 LRS2-2Mix 上是误判——本项目自己已核实 `mix ≈ s1+s2` 的相对 RMSE 只有 1e-4、无 NaN、无近静音源，这是合成混合数据，不存在标注噪声，Q-Tuning 的 Q1 象限没有对应物。C 区的正确表述是「当前容量/当前训练阶段下不可学」，其成因很可能是同性别、同基频区间或低 `2|x|` 混合——**这些是真正有信息的困难样本，不是垃圾**。因此对 C 区限权必须另行论证（例如证明其梯度方差异常大），不能以「去噪」为由直接丢弃。首轮只限权、不清零，并单独统计 C 区在各子集中的占比。

为了防止子集偏离测试分布，每个 50% 子集内保留 25% 的均匀随机探索样本；其余按分数选取，而不是永久删除固定文件。

### 5.1 Gap 信号确实存在，但方差由 pruned 项主导

| | 均值 | sd | min | max |
|---|---:|---:|---:|---:|
| `Q_dense`（TR） | 14.076 | 1.626 | 8.529 | 19.199 |
| `Q_dense`（TT） | 11.393 | 3.480 | −3.860 | 18.375 |
| `Q_pruned@init` | 6.695 | 3.591 | −5.565 | 13.809 |
| `Q_pruned@1ep` | 11.215 | 2.538 | −3.574 | 16.590 |
| `Q_pruned@long` | 13.090 | 1.658 | 7.465 | 17.922 |
| `Gap_dB@init` | 7.382 | 3.370 | **2.786** | 21.942 |

`Gap_dB@init` 的最小值仍有 2.79 dB，即**每一条样本都被剪枝显著损害**，退化是全局性的而非集中在少数样本。同时 `sd(Q_pruned) = 2.2 × sd(Q_dense)`，这正是 §4.2 共线性问题的来源。

### 5.2 dense 教师在训练集上过拟合 2.68 dB

```
dense 在 TR: 14.076 dB (sd 1.63)     dense 在 TT: 11.393 dB (sd 3.48)     差 +2.683 dB
```

`Q_dense` 在训练集上有相当一部分来自记忆而非可学性，会系统性地把「被记住的样本」推进高分集。注意 TR 上的标准差只有 TT 的 47%——记忆同时**压缩了训练集上的难度分布**，进一步削弱了 `Q_dense` 作为可学性度量的分辨力。RHO-LOSS 用独立 holdout 模型正是为规避这一点。本项目无法重训 holdout 模型（136 epoch），改用 §12.1 的分布对比 + 分位截断做抗偏差处理。

### 5.3 静态分数会迅速失效——决定主终点的关键证据

```
Gap_dB 均值:   init 7.382  →  20,000 updates 2.862  →  800,000 updates 0.986

                                   ρ(init, 之后)    top-37.5% 重叠
Gap_dB   init vs 1ep  (20k)            0.484            0.604
Gap_dB   init vs long (800k)           0.253            0.462
Gap_rank init vs 1ep  (20k)            0.429              —
Gap_rank init vs long (800k)           0.246              —
                                   （随机基准 0.000        0.375）
```

在冻结起点算出的分数，20,000 updates 后只保留中等强度的序信息，800,000 updates 后已接近随机（重叠 0.462 vs 随机 0.375）。**把静态子集用于跑几十个 epoch 的实验，等于用一个只在前 1/40 训练时间有效的信号指挥整段训练。** 这是主终点改为固定 40,000 updates 的直接依据，也是 §12.1 静态假设闸门阈值（0.30）的标定来源：20k 窗口的 0.43–0.48 明显过关，800k 窗口的 0.25 明显不过关。

短程内信号确实存在：

```
ρ(score@init, 第一个 epoch 的逐样本实际提升)
    Gap_dB      0.800
    Gap_rank    0.692
    pruned loss 0.649
（该 epoch 的实际提升：均值 +4.520 dB，sd 3.039，min −5.460）
```

⚠️ **这三个相关有一部分是机械的**：`improvement = Q_p1 − Q_p0` 与三个分数都共享高方差的 `−Q_p0` 项，因此不能当作预测力的干净证据，只能当作「短程窗口内信号未失效」的弱旁证。也正因为如此，`Gap_dB` 在这一列排第一**不构成**选它当主方案的理由——它只是与 `−Q_p0` 共线得更彻底。真正的检验只能靠 §9.2 的对照实验。

另外注意 `improvement` 的 min 为 −5.460 dB：第一个 epoch 里有样本是**变差**的，说明恢复过程存在样本间竞争，这也是数据选择可能有价值的机制之一。

### 5.4 算力实测——原矩阵不可行

由 `validation.csv` 的 `elapsed_seconds` 差分测得：

| | A-FRCNN-12 | SuDoRM-RF |
|---|---:|---:|
| 每 epoch（20,000 updates + 5,000 条 CV 验证） | **3,584 s ≈ 59.7 min** | 2,588 s |
| 折算单 update（含验证摊销） | ~0.179 s | ~0.104 s |
| 纯训练单 update（估） | ~0.150 s | — |
| 已完成 | 58 epoch / 57.0 h，best@40 = 10.919 | 80 epoch / 57.1 h，best@72 = 8.498 |

按 v2 的「训练到收敛」口径：best@40 + patience 30 → 每个 arm ≥ 70 epoch ≈ **3 天**；4 个 arm × 3 seed = **约 35 GPU-天**，且当前这张 A100 正被上述两个长程任务占满（`nvidia-smi` util 91%）。不可行。

按 v3 的固定 40,000 updates 口径：每个 run ≈ 40,000 × 0.150 s + 8 次 × 1,000 条验证 × 0.117 s ≈ 6,000 + 936 s ≈ **1.93 h**。详细预算见 §9.5。

## 6. 可参考的数据剪枝方案

### 6.1 第一优先级：低改造成本

| 方法 | 核心做法 | 对当前项目的价值 | 建议 |
|---|---|---|---|
| Random static/dynamic subset | 固定或每周期随机保留固定比例 | 必须有的无偏基线，可测纯数据量收益 | 必跑（S1 / D0） |
| Loss / Easy2Hard | 根据前一轮 per-sample loss，从随机逐渐转向困难样本 | [DDP-ASR](https://www.isca-archive.org/interspeech_2024/xiao24b_interspeech.pdf) 已在语音识别验证动态实例选择 | 动态阶段跑（D1） |
| InfoBatch | 随机丢弃一部分低 loss 样本，并对保留样本重标度以减小梯度偏差 | 架构无关，工程简单；[ICLR 2024](https://proceedings.iclr.cc/paper_files/paper/2024/hash/ad1d7a4df30a9c0c46b387815a774a84-Abstract-Conference.html) | 可选的 loss-only 强基线 |
| Dense–Pruned Gap_rank | 分位空间内优先选择 dense 会而 pruned 不会的样本 | 与结构化剪枝目标最直接协调 | **主方案（S3′）** |
| Dense 知识蒸馏 | 全数据 + dense 输出蒸馏项 | dense 在本设定里零成本可得，是最强的「不做数据选择」对照 | 建议跑（K0），见 §10.4 |

### 6.2 第二优先级：更强但成本更高

| 方法 | 核心做法 | 适配判断 |
|---|---|---|
| RHO-LOSS | 当前模型 loss 减去参考模型的不可约 loss | 思想高适配；本项目 dense 可作恢复目标，但它看过同一训练集（实测过拟合 2.68 dB），不能声称估计了严格的不可约 loss |
| GraNd / EL2N | 用早期梯度范数或输出误差范数评分；[NeurIPS 2021](https://proceedings.neurips.cc/paper/2021/hash/ac56f8fe9eea3e4a365f29f0f1957c55-Abstract.html) | EL2N 的分类概率定义不能直接使用；GraNd 对三种分离模型逐样本求梯度代价较高 |
| Dynamic Uncertainty | 用训练过程中预测变化识别有信息的样本；[CVPRW 2024](https://openaccess.thecvf.com/content/CVPR2024W/DDCV/html/He_Large-scale_Dataset_Pruning_with_Dynamic_Uncertainty_CVPRW_2024_paper.html) | 可迁移为 SI-SDR 的跨 checkpoint 波动，适合第二阶段 |
| Generalization Influence | 近似删除子集对泛化的影响；[ICLR 2023](https://openreview.net/forum?id=4wZiAXD29TQ) | 理论更强，但 Hessian/影响近似成本不适合首轮 |
| MATES | 通过局部 probing 学习动态 data-influence model；[NeurIPS 2024](https://proceedings.neurips.cc/paper_files/paper/2024/hash/c4bec0d2fd217e6c2c3eafeced432582-Abstract-Conference.html) | 对 20k 规模数据和当前模型过重，不建议 |

### 6.3 音频特有方案

- [DDP-ASR](https://www.isca-archive.org/interspeech_2024/xiao24b_interspeech.pdf) 同时研究实例级动态剪枝和 time-wise dropping。论文在 ASR 上发现连续 chunk dropping 比离散 point dropping 更稳，并报告最高约 1.6 倍训练加速。它是 Q-Tuning「sample + token」在音频上的最近似参考，但 ASR 的 CTC/CE 目标与时域分离的波形重建目标不同，不能直接继承结论。
- [Mining Hard Samples Locally and Globally for Improved Speech Separation](https://sigport.org/sites/default/files/docs/MINING_HARD_SAMPLES_LOCALLY_AND_GLOBALLY_FOR__IMPROVED_SPEECH_SEPARATION0212.pdf) 直接面向 speech separation，用 loss 加权或 speaker pitch/x-vector 距离做 hard-sample 重采样。它说明分离任务的数据难度确实可被显式建模，也提醒单纯依赖动态混合 loss 可能只得到局部判断。
- [Cluster-based pruning techniques for audio data](https://arxiv.org/abs/2309.11922) 用音频 embedding 聚类保持代表性，适合做多样性约束，可防止高分选择集中在少数相似说话人/声学条件。
- [Target-specific Dataset Pruning for Compression of Audio Tagging Models](https://eurasip.org/Proceedings/Eusipco/Eusipco2024/pdfs/0000061.pdf) 先按目标域相似度裁剪大规模源数据再蒸馏小模型。若未来加入 LibriMix、WHAM!/WHAMR! 并只服务 LRS2 目标域，这条路线有价值；当前只有同域 LRS2-2Mix 时收益有限。

## 9. 实验设计（v3 主体）

### 9.1 固定预算与调度设定

所有分支从相同冻结输入重建物理模型，重新初始化相同配置的 Adam（lr=1e-3，weight_decay=0），不继承任何现有 optimizer state。

| 项 | 设定 | 理由 |
|---|---|---|
| 训练预算 | **固定 40,000 optimizer updates**（batch size 1） | 静态分数在此之后失效（§5.3）；且这正是 SepPrune 主打的快速恢复窗口 |
| 学习率 | **常数 1e-3，不使用 ReduceLROnPlateau，不 early stop** | 彻底消除调度频率混淆 |
| 训练中验证 | 固定 1,000 条 CV 子集（所有分支完全相同，seed 固定选取），每 5,000 updates 一次，共 8 次 | 全 5,000 条 CV 每次要 ~580 s，占总时长 16% |
| 正式评测 | 完整 3,000 条 TT，在 20,000 与 40,000 updates 两个点 | 与既有结果口径一致 |
| 50% 分支的数据轮次 | 10,000 条子集，40,000 updates = 4 遍 | 全数据分支为 2 遍 |

**常数 LR 的合法性已核实**：现有 `finetune/training.csv` 与 `validation.csv` 显示学习率在 step 1 至 460,000 之间恒为 1e-3（ReduceLROnPlateau 的 patience=15 个验证事件，在前 40,000 updates 内不可能触发）。因此关闭调度器不改变前 40,000 updates 的优化过程。

**S0 完整重跑，不复用 `epoch1.pt` 作为训练状态**（v3.1 修正）：`finetune/epoch1.pt` 的 `global_step` 恰为 20,000、起点与 seed 也一致，一度计划让 S0 从它续跑到 40,000 以省约 1 小时。但该 checkpoint 前 20,000 步的数据顺序来自旧 DataLoader 的 shuffle，与新脚本的确定性 order 不同，拼接会让 S0 的口径难以描述。为 1 小时牺牲干净性不划算，**S0 从冻结起点完整重跑 40,000 updates**。`epoch1.pt` 只提供一个纯数值：它在完整 3,000 条 TT 上的 **10.933 SDRi / 10.522 SI-SDRi**，作为 §9.3 中 E2 恢复阈值的预注册来源。

### 9.2 阶段 A：静态数据选择

先用冻结的 dense 与 pruned@init 对全部 TR 打分一次（一次性成本，服务所有 score-based arm 与所有 seed）。所有 50% 分支永久保留恰好 10,000 条。

| 实验 | 保留率 | 子集构造 | 角色 |
|---|---:|---|---|
| **S0** | 100% | 全部 20,000 条 | 同起点上界基线（20k 锚点免费） |
| **S1** | 50% | 固定均匀随机 10,000 条 | 静态数据量基线 + 功效闸门 |
| **S2** | 50% | pruned loss top 7,500 + 其余中随机 2,500 | 传统 hard mining 基线 |
| **S3** | 50% | `Gap_dB` top 7,500 + 其余中随机 2,500 | **消融**：证明未分位化的 Gap 退化为 hard mining |
| **S3′** | 50% | **`Gap_rank` top 7,500 + 其余中随机 2,500** | **主方案** |
| S4 | 50% | `pct_dense × Gap_rank` 二维分层 7,500 + 随机 2,500 | **暂缓**，实测反而更接近 hard mining，见下 |
| K0 | 100% | 全数据 + dense 输出蒸馏项 | 「不做数据选择」的强对照，见 §10.4 |

约束：

- 「25% 随机探索」指**保留预算内部的 25%**，即 10,000 条中的 2,500 条；两部分无重复，且随机部分只从未被分数选中的 12,500 条中抽取。
- S1/S2/S3/S3′/S4 使用**完全相同的 `|SNR|` 分位区间配额**（按 TR 的四分位分 4 层），排序和随机探索均在各分层内完成，避免只有主方案额外获得分布约束。
- 首轮只**审计**说话人覆盖，不为任何单一方法加 speaker cap。若高分选择发生覆盖坍缩，再新增一个明确标注的 diversity ablation。
- 必须报告 **S2/S3/S3′ 三者两两的子集重叠率**，作为「这些 arm 是否构成真实对照」的设计合理性证据。全 20,000 条上的实际重叠可能与 §4.2 的 600 条估计有出入，以实际值为准；`audit_selection.py` 会自动输出。

> **S4 暂缓的原因（v3.1，实测）**：在 400 条真实分数上跑完整 sampler 后，各 arm 与 S2（纯 hard mining）的 score-selected 重叠为 `S3′ 0.620 < S3 0.820 < S4 0.847`。S4 反而是最接近 hard mining 的。原因是可推的：在一个很窄的 `pct_dense` 带内部，按 `Gap_rank` 排序等价于按 `-pct_pruned` 排序，二维分层把 dense 轴的区分作用消掉了。因此 S4 不能承担「解耦 arm」的角色。若后续仍要它，应改成按 `pct_dense` **分层配额但仍用全局 `Gap_rank` 排序**，或直接换成显式排除 C 区的构造。sampler 已实现 `gap_rank_2d`，随时可跑，但不进 A1。

### 9.3 主终点与统计

两个预注册主终点：

- **E1（方向 B，固定预算性能）**：完整 3,000 条 TT 的 SI-SDRi，在 20,000 与 40,000 updates 两个点。
- **E2（方向 A，训练效率）**：达到**预注册恢复阈值 10.522 dB TT SI-SDRi**（即 S0 在 20,000 updates 的既有结果）所需的 updates 数与端到端墙钟。

次要终点：SDRi；easy/medium/hard 三个测试分位组的 SI-SDRi；1,000 条 CV 的恢复曲线。

统计规程（预注册）：

- 最小可检测效应 **MDE = 0.15 dB TT SI-SDRi**。低于此值的差异一律报告为「无法区分」，不解释方向。
- **E1b（2026-08-14 补充预注册，方差缩减终点）**：30,000 与 40,000 updates 两个快照的 TT SI-SDRi **平均值**。补充理由与时点必须如实记录：A0 闸门测得 seed 间 sd 在 20,000 updates 处为 0.032 dB、在 40,000 处升到 0.088 dB，后者对应 3 个 seed 下 0.200 dB 的最小可检测差，达不到 0.15 的 MDE。单点终点的噪声主要来自训练末端的抖动，取相邻两个快照平均可压低它。**本条在 A1 启动之前、且在看到任何 arm 间比较之前写定**；A0 只跑了 S1 单个 arm，没有产生任何 arm 间比较结果。E1（40,000 单点）仍为主终点，E1b 为并列报告的次要终点，两者结论不一致时以 E1 为准并如实说明分歧。
- 因此快照点由 `20000,40000` 改为 `20000,30000,40000`。
- 主检验为 3,000 条测试样本上的**配对 bootstrap**（同一 arm 内跨 seed 先取平均，再对样本重采样 10,000 次），报告差值的 95% CI，而不只是均值 ± 标准差。
- Seed 为配对设计：seed 只控制随机探索抽样与数据顺序 RNG；初始模型由 dense+masks 确定性重建，各 arm 完全一致（需校验 state dict 哈希）。

### 9.4 效率口径（必须严格区分三种说法）

⚠️ **在 batch size = 1、固定 update 预算下，50% 分支不产生任何墙钟节省**——每个 update 的成本与全数据分支完全相同。因此：

| 口径 | 含义 | 是否可称为「加速」 |
|---|---|---|
| 固定 updates | 双方计算量相同，只比精度 | ❌ 只能称「数据效率」 |
| 固定数据轮次（epoch） | 50% 分支每 epoch 少一半 update | ❌ 这只是少算了一半，不是加速 |
| **达到同一精度阈值所需总墙钟** | E2 | ✅ 唯一可称「训练加速」的口径 |

打分成本必须计入 E2，并按两种口径各报一次：**单次实验口径**（打分成本全额计入一个 run）与**摊销口径**（一次打分服务全部 score-based arm 与 seed）。数据评分、验证和 checkpoint I/O 时间单列。

### 9.5 分阶段算力预算与并发

**本阶段不依赖任何仍在进行的长程微调。** Stage A 的四个冻结输入（dense `best.pt`、`masks.pt`、E2 阈值 10.522 dB、静态闸门用的 `epoch1.pt`）全部已最终确定，且都不来自长程分支。v2 曾把长程曲线设想为 S0 基线，v3 把主终点改成固定 40,000 updates、S0 从冻结起点重跑之后，这条依赖已经断开。长程微调只产出论文复现表里的「剪枝后收敛值」，是另一条交付线。

**GPU 可以并发（实测）。** batch size = 1、3M 参数的模型在 A100 上是 kernel launch 延迟受限而非算力受限，`nvidia-smi` 的 94% 利用率具有误导性。实测（A-FRCNN-12，40,000 updates 等效）：

| 并发任务数 | 每路 ms/step | 相对 2 路 | 聚合吞吐 | 单 arm 40k updates |
|---:|---:|---:|---:|---:|
| 2（仅两个长程） | 173.7–177.8 | — | 5.6–5.8 step/s | 1.98 h |
| 3（+1 个 stage-A） | 180.0 | +3.7% | 11.2 step/s | 2.00 h |
| 5（+3 个 stage-A） | 251.3–252.4 | +41.6% | 15.9 step/s | 2.80 h |

显存不是瓶颈（5 路合计约 5.2 GB / 40 GB）。**第二个任务几乎免费；三个 stage-A arm 并跑 2.80 h 完成，串行则要 5.94 h。** 三个并发 arm 实测速率为 252.4 / 251.3 / 251.5 ms/step，彼此差异 <0.5%，条件是公平的。

因此按**每批 3 个 arm 并发**编排：

| 阶段 | 内容 | 批次 | 估算 |
|---|---|---:|---:|
| A0 打分 | 全 TR × dense/pruned，batch 32 | — | ~0.4 h |
| **A0 功效闸门** | S1 × 3 seeds，同批并发 | 1 | ~2.8 h |
| **A1 筛选** | S0、S2、S3、S3′（+K0）× seed 2026 | 2 | ~5.6 h |
| **A2 确认** | 存活 arm × 另外 2 seeds | 2–3 | ~5.6–8.4 h |
| TT 评测 | 每 run 2 个检查点，batch 1 | — | ~8–12 h |
| 合计 | | | **~23–29 h** |

**E2 的公平性约束（因并发而新增）**：墙钟只在**相同后台负载**下可比。因此

- 需要互相比较的 arm 必须放进**同一批并发**（同批内实测速率差 <0.5%）；
- 每个 run 在 `config.json` / `result.json` 中记录 `gpu_processes_at_start` / `gpu_processes_at_end` 与 `ms_per_update`，跨批比较墙钟前必须核对这三个字段一致；
- 若两个 arm 的并发度不同，只报告 E1（固定 update 下的精度，对墙钟免疫），不报告 E2。

**A0 功效闸门的判据**：S1 三个 seed 的 TT SI-SDRi 标准差若 ≥ 0.15 dB（= MDE），则整个矩阵分辨不出方法差异，必须先增加 seed 数或改用配对样本级检验，不得直接进入 A1。

### 9.6 阶段 A3：动态方法（仅在静态 S3′ 优于 S1 后启动）

| 实验 | 保留率 | 动态策略 |
|---|---:|---|
| D0 | 50% | 每个 selection cycle 重新均匀随机 |
| D1 | 50% | Easy2Hard，始终包含保留预算内 25% 的随机探索 |
| D2 | 50% | dense 分数固定，pruned 分数**每 5,000–10,000 updates** 重算一次，再算 `Gap_rank` |

> **v3 修正**：v2 定的刷新周期是「每 5 个 full-data-equivalent round」（即 100,000 updates）。由 §5.3 实测，Gap 在 20,000 updates 内就衰减过半，该周期太慢。改为 5,000–10,000 updates 量级，并在实验开始前固定，不得根据 CV 结果事后挑选。每次刷新的前向时间必须计入 E2 的总墙钟。

| B0 | 50% | 2.0 s | A 阶段胜者 |

### 10.4 关于 K0（dense 蒸馏对照）

dense 模型在本设定中零成本可得（pruned 权重就是从它继承的）。审稿人必然会问：既然用 dense 当教师来*挑数据*，为什么不直接用它*做蒸馏*？K0 使用全数据 + dense 输出蒸馏项，其余设定与 S0 完全一致。它不是本方案的竞品而是定位锚：

- 若 S3′ 优于 K0 → 数据选择本身有独立价值；
- 若 K0 明显更优 → 应把论述改为「dense 教师的正确用法是蒸馏」，数据选择降级为附加项；
- 两者可叠加（蒸馏 + 选择）是自然的后续。

**实现（`distill_baseline.py`，已完成）**：

```text
L = (1 - α) · PIT-NegSNR(student, targets)
  +      α  · NegSNR(student, teacher | 与任务项相同的排列)
```

两个排列细节决定它是「正确」而不是「大致正确」：

1. **教师输出先对齐到 ground truth**：教师的两个输出通道按其自身 PIT 最优排列重排，使「教师源 0」与「目标源 0」始终指同一个说话人。
2. **蒸馏项复用任务项选中的排列**，而不是自己再跑一次 PIT。否则两项可能把同一个输出通道往两个不同的说话人上拉。教师足够好时二者几乎总是一致，但「几乎总是」不是可以写进损失函数的性质。

教师全程 `eval()` + `requires_grad_(False)` + `no_grad`，验收中断言 `teacher.grad is None`。

**关键性质与代价**（均已实测）：

| 项 | 结果 |
|---|---|
| `α=0` 是否与 S0 逐位一致 | ✅ `max|Δweight| = 0.0`（6 步），证明新代码路径在关闭时完全惰性 |
| 首步任务项是否等于 S0 的 loss | ✅ 均为 `-3.2722`（同一起点，之后按设计分叉） |
| 每 update 成本 | S0 0.336 s → **K0 0.379 s，+13%**（教师前向；教师 5,127,688 参数 vs 学生 3,059,372） |

⚠️ **K0 因此不是算力对齐的 arm**。在固定 40,000 updates 下它多花约 13% 墙钟，比较时只能在**相同 update 数**下读精度，墙钟必须单列。默认 `α=0.5`；若首轮结果对 α 敏感，需补 α 消融而不是挑一个好看的值。

K0 增加约 3 个 run（~7 h），可单独砍掉而不影响 S0–S3′ 的主结论；它不在 `ARMS` 默认值里，需显式 `ARMS="K0"` 启动。

### 12.1 评分器

- 同一个模型同时作为 dense/pruned 输入时，逐样本 Gap 应在数值误差范围内为 0；
- 交换模型的两个输出源顺序，不应改变 PIT SI-SDR 和 Gap；
- `gap_db == q_dense_sisdr - q_pruned_sisdr` 逐行成立；`gap_rank == pct_dense - pct_pruned` 逐行成立；
- **batch 打分与 batch=1 打分的逐样本结果一致**（容差 1e-4）；若同时记录训练口径的 PIT-NegSNR，必须断言 `threshold_byloss=False`（该开关在 batch=1 时是 no-op，batch>1 时会真的丢样本）；
- 评分器全程 `eval()` + `inference_mode()`，无参数梯度、无随机数据增强；
- checkpoint/mask SHA256 不匹配时立即失败，不能只给 warning；
- 每个训练文件名恰好出现一次，输出 20,000 行，无 NaN/Inf；
- **抗过拟合偏差检查（v3 新增）**：同时对 CV（held-out）打 dense 分数，对比 `Q_dense(TR)` 与 `Q_dense(CV)` 的分布（均值、分位数、形状）。已知均值差约 2.68 dB，且 TR 上的 sd 仅为 TT 的 47%。若 `Gap_rank` 的高分集显著偏向 `Q_dense` 的极高尾，则对 `pct_dense` 做上侧 5% 截断后重算，并把两个版本的子集重叠率记入日志；
- **静态假设闸门（v3 新增）**：用 `finetune/epoch1.pt` 在全 TR 上重算一次 pruned 分数，报告 `ρ(Gap_rank@init, Gap_rank@1ep)`。若该值低于 0.30，说明连 20,000-update 窗口内静态分数都已失效，应直接跳到 §9.6 的动态方案，不再投入静态 arm 的 seed 扩展。

### 12.2 子集与 sampler

- 每个 50% 子集恰好 10,000 个唯一文件名，只能来自 TR；
- score 选择 7,500 条、random exploration 2,500 条，二者交集为空，且随机部分只从未被选中的 12,500 条中抽取；
- S1/S2/S3/S3′/S4 的 `|SNR|` 分层配额完全一致；
- 输出 S2/S3/S3′ 两两重叠率；若 S3 与 S2 的重叠 > 0.80（§4.2 的 600 条估计为 0.822），在报告中明确标注「S3 与 S2 不构成有效对照，仅作共线性证据」；
- 相同 seed 生成完全一致的列表，不同 seed 只改变明确声明的随机部分；
- 保存实际样本清单及其哈希，训练恢复时重新核对。

### 12.3 训练公平性

- 所有分支从相同 dense checkpoint + masks 重建模型，并验证初始 state dict 哈希一致；
- optimizer 都从空状态创建，超参数一致；常数 LR，无 scheduler，无 early stop；
- 验证在相同 global step 触发，使用完全相同的 1,000 条 CV 子集；
- **S0 复用 `epoch1.pt` 作为 20,000-update 锚点前，必须核对其 `global_step == 20000`、`parameters == 3059372`、seed 与 LR 记录一致**（已核对通过）；
- smoke 阶段先跑 S0/S1/S3′ 各 200–500 updates，核对 loss、梯度、显存、吞吐和 resume；
- 新的 `train_data_pruned.py` 必须支持按 global step 精确 resume，不能靠遍历 dataloader 跳过 batch（现有 `train_pruned_original.py` 的 `if batch_index < resume_at: continue` 在 40,000-update 预算下尚可接受，但会重复读盘）；
- 正式测试前锁定选择规则、恢复阈值、MDE 和 seed，不依据 TT 结果回改方案。

### 12.4 结论边界

- 若 S3′ 只在固定 updates 下更好、但 E2 的墙钟（含打分时间）更差，只能报告「数据效率提升」，**不得报告「训练加速」**（见 §9.4）；
- 若 S1 三 seed 的标准差 ≥ MDE，先解决功效问题，不得报告任何方法间比较；
- 若 S3′ 不优于 S2 且两者子集重叠 < 0.70，说明收益主要来自 hard-example mining 而非模型剪枝协同，应如实报告；
- 若 S3′ 不优于 S1，停止扩展动态和时间级实验，先分析分数分布与子集偏差；
- 若 K0（蒸馏）明显优于 S3′，应把 dense 教师的定位改为蒸馏，数据选择降级为附加项；
- 若只在 A-FRCNN-12 有效，应称为 model-specific 结果，不能推广到三个模型；
- 全程不得声称本方案降低了参数量或 MAC（见第 0 节）。

### 13.2 实现阶段发现的两个数值问题（v3.1）

**1. 打分器必须关闭 TF32，否则子集不可复现。** A100 上 cuDNN 卷积默认启用 TF32（而 cuBLAS matmul 默认不启用，两者不对称）。实测同一批 16 条真实音频，batch 16 与 batch 1 的逐样本 SI-SDR 差异：

| | TF32 开（默认） | TF32 关 |
|---|---:|---:|
| dense | 7.7e-4 dB | 2.9e-6 dB |
| pruned@init | 1.6e-3 dB | 5.7e-6 dB |

20,000 条分数分布在约 19 dB 上，**相邻名次的平均间距就是 ~1e-3 dB**，与 TF32 噪声同量级，足以打乱相邻样本的 percentile rank。因此 `score_lrs2.py` 无条件关闭 TF32（`common.set_tf32(False)`，只用 legacy 开关——新旧 API 混用会被 PyTorch 拒绝）。训练脚本则**不修改默认值**，只读取并记录，以保持与既有 finetune 流水线的数值可比；`--disable-tf32` 可选开启。

**2. 共享 GPU 上不存在逐位确定性，验收判据要选对。** 两次完全相同的从头训练在 GPU 空闲时逐位一致（Δ=0.0，72/72 张量），但当另外两个长程任务同时占用显存时，cuDNN 的显存感知算法启发式可能换算法，8 个 Adam step 内即放大到 3e-3。因此 resume 验收**不断言逐位相等**，而是断言逐步 loss 轨迹在 1e-2 dB 容差内一致——数据顺序若出错，单步 loss 会有 dB 量级偏差，这个判据抓得住真 bug 又不会被内核噪声误报。这一点也意味着：**A0 功效闸门测到的 seed 间标准差里，天然包含一部分硬件噪声**，这是正确的口径，不应试图消除。

### 13.3.2 可以下的结论

1. **没有任何数据选择方法与全数据或彼此可区分。** 包括主方案 `Gap_rank`。子集构造本身是成功的——全量审计确认 S3′ 与 hard mining 的重叠只有 0.594、A 区占比 57.7% vs 全集 34.4%——但这个选择差异**没有转化为可测量的恢复性能差异**。
2. **在 40,000 updates 预算下，50% 数据（含均匀随机）达到全数据水平。** 这是本阶段唯一稳固的正面结果。按 §9.4 的口径，它只能称为**数据效率**，不能称为训练加速：固定 update 下 50% 分支不省任何墙钟。
3. **数据量在更早的时候确实起作用，随后饱和。** @20k（全数据 1 遍 vs 50% 2 遍）S0 领先 0.04–0.08 dB；到 @40k（2 遍 vs 4 遍）追平。与「独特样本在早期有用、之后饱和」一致。
4. **K0 蒸馏在数值上最高**（两个终点都是），但同样低于 MDE，也不构成胜出。§12.4 中「若 K0 明显更优则改述」的条件未触发。

### 13.3.3 对方案的影响与建议

§12.4 的两条边界条件都指向同一处：**保留率 50% 已经饱和，选择规则在这个工作点上没有发挥空间。** 继续加 seed 不是出路——要把 0.05 dB 的效应做到显著需要每个 arm 约 10 个 seed（约 50 个 run、35 GPU-小时），而 0.05 dB 在语音分离里本来就不是有意义的改进。

因此**不建议**执行原计划的 A2（补 seed）、A3（动态刷新）和阶段 B（时间子段）——它们都建立在「静态选择在 50% 上有效」这个已被证伪的前提上。

建议改为把**保留率本身**作为变量。Q-Tuning 用的是 12.5%，而我们在 50% 上测到的是饱和区。下一个实验应是同一套代码、同一套终点，把 `--keep` 降到 2,500（12.5%）跑 S1 / S2 / S3′ × 3 seed（9 个 run，2 批，约 7 h），看：

- 在 12.5% 上全数据与随机子集是否终于拉开差距（即找到饱和点）；
- 若拉开，`Gap_rank` 是否在这个更紧的预算下胜过随机与 hard mining。

如果 12.5% 上仍然无差异，那么结论就是「LRS2-2Mix 上剪枝模型的恢复对训练数据的选择与数量都高度不敏感」——这本身是一个干净、可发表的负面结果，且比强行在噪声里找 0.04 dB 诚实得多。

### 13.4.2 下一步实验（已启动）

在 keep=2,000（10%）上比较 S1 随机 / S2 hard mining / S3′ gap_rank × 3 seed，共 9 个 run **单批并发**（9 路同时跑，条件完全一致，这是 E2 与 arm 间比较最干净的编排）。

| 保留率 | 随机相对 S0 的缺口（E1c） | S3′ − S1 | 补回比例 |
|---:|---:|---:|---:|
| 50% | 0.019（噪声量级） | +0.023 | — |
| 10% | 0.270 | +0.100 | 37% |
| **5%** | **0.603** | **+0.162** | **27%** |

绝对效应随稀缺程度单调增大并在 5% 处越过 MDE。**但补回比例并不恒定**（37% → 27%）：§13.6.2 曾按「比例恒定」外推 5% 会得到约 0.29 dB，实际为 0.162。**方向预测正确，幅度高估**，这一点必须如实记录，不能事后把外推说成预测成功。

同时必须注意绝对水平：S3′ 在 5% 上的 10.172 仍远低于全数据的 10.613。选择规则补回的是随机子采样损失的四分之一到三分之一，**不是让 5% 数据追平全数据**。

### 13.7.3 分位化改造的消融（n=5，已完成）

| arm | @10k | @20k | @30k | @40k | **E1c** | sd |
|---|---:|---:|---:|---:|---:|---:|
| S2 hard mining | 9.894 | 9.980 | 9.901 | 9.883 | **9.941** | 0.028 |
| S1 随机 | 9.990 | 10.047 | 9.974 | 9.997 | **10.010** | 0.055 |
| S3 gap_dB | 10.081 | 10.053 | 10.086 | 9.964 | **10.069** | 0.038 |
| **S3′ gap_rank** | 10.158 | 10.190 | 10.155 | 10.081 | **10.172** | 0.033 |

主终点 E1c 的全部两两配对检验（n=5，df=4，MDE=0.15）：

| 对比 | Δ | t | p | 判定 |
|---|---:|---:|---:|---|
| **S3′ − S1 随机** | **+0.162** | 5.56 | 0.0051 | **✓ 过阈** |
| **S3′ − S2 hard** | **+0.232** | 14.21 | 0.0001 | **✓ 过阈** |
| S3′ − S3 gap_dB | +0.103 | 3.90 | 0.0176 | 显著但 < MDE |
| S3 − S2 hard | +0.129 | 4.92 | 0.0079 | 显著但 < MDE |
| S2 − S1 随机 | −0.070 | −3.67 | 0.0214 | 显著但 < MDE |
| S3 − S1 随机 | +0.059 | 2.09 | 0.1047 | 不显著 |

**判定：分位化改造「不能声称是实质性必要的」，但「只有分位形式能过线」。** 两句话都要说，缺一句都会失真：

- 直接对比 `S3′ − S3 = +0.103 dB`（p=0.018）统计显著，但低于预注册的 MDE 0.15，按 §9.3 必须报为无法区分，不解释方向；
- 然而在与两个基线的对比上，**只有 `gap_rank` 同时过阈**。`gap_dB` 相对随机 +0.059（p=0.105，**连显著都不到**），相对 hard mining +0.129（显著但低于 MDE）。

也就是说：不能说「分位化比 dB 差好 X dB」，但可以说「按预注册标准，本研究只在分位形式上观察到了相对随机基线的实质性收益；未分位化的 dB 差形式没有达到该标准」。这与 §4.2 当初做这项改造的理由一致——那里的论证是「dB 差与 hard mining 共线 0.809，不构成有效对照」，本节数据也吻合：keep=1,000 上 gap_dB 与 hard 的子集重叠为 0.679，而 gap_rank 仅 0.237。

### 13.7.4 阶段 A 完整结论

| 保留率 | 随机相对全数据的损失 | S3′ − 随机 | 过阈 |
|---:|---:|---:|:--:|
| 50% | 0.019（无损失） | +0.023 | ✗ |
| 10% | 0.270 | +0.100 (p=0.017) | ✗ 低于 MDE |
| **5%** | **0.603** | **+0.162 (p=0.005)** | **✓** |

**可以声称的**：

1. 在剪枝模型的恢复任务上，**数据选择只在数据严重稀缺（≤5%）时产生实质收益**；此时用 dense 教师条件化的分位差选择显著优于均匀随机（+0.162 dB）与 hard mining（+0.232 dB）。
2. **纯 hard mining 在稀缺预算下比随机更差**（−0.070 dB，p=0.021），机理为它系统性偏向「两个模型都做不好」的不可约难例（其子集平均 `Q_dense` 13.60 低于全集 14.10）。这是「必须用 dense 条件化」的直接证据。
3. **50% 均匀随机子集即可无损匹配全数据**（−0.019 dB）。这是本研究实用价值最高的观察，且**不需要任何选择方法**。

**不能声称的**：

1. 「数据剪枝加速了剪枝模型的恢复」——固定 update 预算下 50% 分支不省任何墙钟（§9.4），全程没有测得 wall-clock 收益，只能称数据效率。
2. 「本方法让 5% 数据达到全数据效果」——5% 上 S3′ 为 10.172，全数据为 10.613，仍差 0.44 dB；选择规则只补回随机子采样损失的 27%。
3. 「分位化改造带来了 X dB 提升」——见 §13.7.3。
4. 任何跨模型/跨数据集的推广——全部结果仅来自 A-FRCNN-12 × LRS2-2Mix 的单一剪枝结构（3,059,372 参数）。

**效应量级的定位**：0.162 dB。作为对照，本地剪枝相对 dense 的差距是 0.010 dB，剪枝本身削减了 40.3% 参数。该效应可测、可复现（5 个 seed 逐一分离），但不足以改变实际的工程选择。

## 14. 最终定位

可以做，且当前结果模型具备适配基础；但命名必须准确：称为 **「结构化模型剪枝感知的数据剪枝」** 或 **「Dense–Pruned 分位差协同选择」**，不要称为 Q-Tuning 的直接复现，也不要暗示它降低了模型参数量。

第一轮只在 A-FRCNN-12 上做 A0 闸门 + A1 筛选（并发编排下约 9 h 训练 + 评测），就能回答最关键的问题：在同一冻结起点、同一 40,000-update 预算下，`Gap_rank` 是否比随机选择和普通 hard mining 更有利于剪枝模型的快速恢复。得到肯定结果后，再补 seed、加二维选择、动态刷新、时间子段和跨模型验证。
